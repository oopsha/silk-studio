# Silk BE Studio 로드맵

> 상태: 기획 단계  
> 마지막 갱신: 2026-09-26

현재 논의 상태와 다음 작업은 [인수인계 문서](./HANDOFF.ko.md)를 참고한다.

## 제품 방향

Spring, Node.js, Python, PHP 백엔드 프로젝트를 개발하고 운영 흐름을 확인할 수 있는 데스크톱 개발 스튜디오를 만든다. Silk DB Studio와 연계해 프로젝트, 애플리케이션 실행, 로그, API, 데이터베이스 작업을 한곳에서 이어가는 경험을 목표로 한다.

초기 제품은 IntelliJ나 VS Code 전체를 대체하려 하지 않는다. 기존 편집기와 언어 도구를 활용하고, 백엔드 개발에 필요한 실행·관찰·DB 연계 경험에 집중한다.

## 지원 우선순위

1. **Spring** — Java 기반 Spring Boot 프로젝트를 우선 지원한다. Kotlin은 사용자 수요와 구현 비용을 확인한 뒤 범위에 포함한다.
2. **Node.js** — JavaScript 및 TypeScript 기반 서버 프로젝트
3. **Python** — 우선 지원할 웹 프레임워크는 수요 조사 후 선정
4. **PHP** — 우선 지원할 웹 프레임워크는 수요 조사 후 선정

## 단계별 계획

### 0단계: 제품 및 기술 검증

- 저장소의 Tauri 앱 구조와 공용 `silk-ui`, `silk-editor`, `silk-workbench` 재사용 가능성 점검
- 코드 분석, 자동완성, 실행, 디버깅을 언어별 도구와 연결하는 구조 검토
- 프로젝트 파일 접근, 프로세스 실행, 터미널, 포트 감지 등 데스크톱 권한 경계 설계
- Spring Boot(Java) 사용자 흐름을 기준으로 첫 릴리스 범위 확정

**완료 기준:** 첫 지원 대상의 프로젝트 열기부터 실행·로그 확인까지 필요한 화면과 기술 경계가 결정됨.

### 1단계: 공통 BE 워크벤치

- 프로젝트 폴더 열기 및 파일 탐색
- 코드 편집기와 탭, 기본 검색
- 개발 서버 실행·중지 및 콘솔 로그 확인
- 실행 설정과 프로젝트별 사용자 설정
- 오류와 프로세스 종료 상태 표시

**완료 기준:** 지원 대상 프로젝트를 열고 개발 서버를 실행해 로그를 확인할 수 있음.

### 2단계: Spring Boot 지원

- Maven 및 Gradle 프로젝트 감지
- Spring Boot 실행 설정과 프로파일 선택
- Java 코드 탐색·진단·자동완성 연동 방식 확정 및 구현
- 실행 로그와 애플리케이션 상태 확인
- REST API 요청·응답 작업 공간
- Silk DB Studio 연결 흐름 검토 및 최소 연동

**완료 기준:** 일반적인 Spring Boot 프로젝트의 개발·실행·API 확인·DB 접근 흐름을 한 앱에서 이어갈 수 있음.

### 3단계: Node.js 지원

- `package.json` 기반 프로젝트 감지
- npm, pnpm, yarn 스크립트 선택 및 실행
- JavaScript/TypeScript 서버 실행과 디버깅 연동
- API 작업 공간과 DB 연동 재사용

**완료 기준:** 대표적인 Node.js 서버 프로젝트를 열고 실행·디버깅할 수 있음.

### 4단계: Python 지원

- 가상 환경 및 의존성 도구 감지
- 선정한 웹 프레임워크의 실행 설정
- Python 서버 실행·디버깅 연동
- API 및 DB 작업 흐름 재사용

**완료 기준:** 선정 프레임워크의 일반 프로젝트에서 실행·디버깅·API 확인이 가능함.

### 5단계: PHP 지원

- Composer 프로젝트 감지
- 선정한 웹 프레임워크의 실행 설정
- PHP 서버 실행·디버깅 연동
- API 및 DB 작업 흐름 재사용

**완료 기준:** 선정 프레임워크의 일반 프로젝트에서 실행·디버깅·API 확인이 가능함.

## 공통 품질 목표

- 언어별 지원 기능과 필요한 외부 런타임을 명확하게 안내한다.
- 프로젝트 실행 명령과 환경 변수는 사용자가 확인하고 제어할 수 있게 한다.
- 프로젝트 간 설정을 분리하고 민감 정보는 평문으로 저장하지 않는다.
- 앱별 기능은 `apps/silk-be-studio`에 두고, 실제로 양쪽 앱에서 재사용되는 기반만 공용 패키지로 추출한다.
- 구체적인 언어 서버, 디버거, API 도구 및 프레임워크 선택은 각 단계의 검증 후 확정한다.
