# Silk BE Studio 로드맵

> 상태: 공용 워크벤치 기반 연결 중
> 마지막 갱신: 2026-09-27

현재 논의 상태와 다음 작업은 [인수인계 문서](./HANDOFF.ko.md)를 참고한다.

## 제품 방향

Spring, Node.js, Python, PHP 백엔드 프로젝트를 개발하고 운영 흐름을 확인할 수 있는 데스크톱 개발 스튜디오를 만든다. Silk DB Studio와 연계해 프로젝트, 애플리케이션 실행, 로그, API, 데이터베이스 작업을 한곳에서 이어가는 경험을 목표로 한다.

초기 제품은 IntelliJ나 VS Code 전체를 대체하려 하지 않는다. 기존 편집기와 언어 도구를 활용하고, 백엔드 개발에 필요한 실행·관찰·DB 연계 경험에 집중한다.

## 지원 우선순위

1. **Spring** — Java 기반 Spring Boot 프로젝트를 우선 지원한다. Kotlin은 사용자 수요와 구현 비용을 확인한 뒤 범위에 포함한다.
2. **Node.js** — JavaScript 및 TypeScript 기반 서버 프로젝트
3. **Python** — 우선 지원할 웹 프레임워크는 수요 조사 후 선정
4. **PHP** — 우선 지원할 웹 프레임워크는 수요 조사 후 선정

## 단계별 계획

### 0단계: 제품 및 기술 검증

- DB Studio의 React/Vite/Tauri 구조와 공용 `silk-ui`, `silk-editor`, `silk-workbench` 재사용 경계 확인
- Spring Boot(Java) 프로젝트 열기, Maven/Gradle 감지, 실행·중지, 로그 확인으로 첫 구현 흐름 구체화
- 프로젝트 파일 접근 및 하위 프로세스의 실행·종료·출력 전달에 필요한 앱 권한 경계 설계
- Java 언어 서버 후보와 런타임 요구 사항을 확인하고 배포·라이선스 검증 항목 기록
- API 요청, DB Studio 연계, 디버깅은 첫 실행 흐름 검증 뒤 포함 시점을 결정

**완료 기준:** 첫 구현 범위가 프로젝트 열기, 빌드 도구 감지, Spring Boot 실행·중지, 로그 확인으로 정해지고, 공용 패키지 재사용 범위와 파일·프로세스 권한 경계 및 Java 언어 도구 검증 항목이 문서화됨.

### 1단계: 공통 BE 워크벤치

- Tauri 앱과 React/Vite 프런트엔드의 실행 골격
- DB Studio와 공용 `silk-workbench` 기반으로 워크벤치 레이아웃 구성
- 프로젝트 폴더 열기 및 파일 탐색
- 코드 편집기와 탭, 기본 검색
- Spring Boot 프로젝트에서 Maven/Gradle 실행·중지 및 콘솔 로그 확인
- 실행 설정과 프로젝트별 사용자 설정
- 오류와 프로세스 종료 상태 표시

**완료 기준:** Spring Boot 프로젝트를 열고 빌드 도구를 감지해 개발 서버를 실행·중지하고 로그와 종료 상태를 확인할 수 있음.

**현재 진행:** Tauri 앱 골격과 공용 TitleBar, ActivityBar, Sidebar, SecondarySidebar, StatusBar, EditorGroupsView를 연결했다. ActivityBar와 Sidebar는 공용 컨테이너이고 각 앱이 뷰와 내용을 등록한다. DB Studio는 DB 연결 탐색기·검색·쿼리 기록을, BE Studio는 파일 탐색기·검색·소스 제어·실행 및 디버그 뷰 골격을 표시한다. 프로젝트 열기·생성, Git 연동, 실행 기능은 구현 전이다.

### 2단계: Spring Boot 지원

- Spring Boot 실행 설정과 프로파일 선택
- JDT Language Server 등 Java 언어 도구 후보의 기능·라이선스·배포 조건 검증 후 코드 탐색·진단·자동완성 연동
- 애플리케이션 준비 상태와 실행 URL 확인
- Java 디버깅 도구 연동 가능성 검증 및 구현 여부 결정
- REST API 요청·응답 작업 공간
- Silk DB Studio 연결 흐름 검토 및 최소 연동

**완료 기준:** 일반적인 Spring Boot 프로젝트에서 언어 지원, 실행·관찰, API 확인 및 최소 DB 접근 흐름을 사용할 수 있음.

### 3단계: Node.js 지원

- `package.json` 기반 프로젝트 감지
- npm, pnpm, yarn 스크립트 선택 및 실행
- JavaScript/TypeScript 서버 실행과 디버깅 연동
- API 작업 공간과 DB 연동 재사용

**완료 기준:** 대표적인 Node.js 서버 프로젝트를 열고 실행·디버깅할 수 있음.

### 4단계: Python 지원

- 가상 환경 및 의존성 도구 감지
- 선정한 웹 프레임워크의 실행 설정
- Python 서버 실행·디버깅 연동
- API 및 DB 작업 흐름 재사용

**완료 기준:** 선정 프레임워크의 일반 프로젝트에서 실행·디버깅·API 확인이 가능함.

### 5단계: PHP 지원

- Composer 프로젝트 감지
- 선정한 웹 프레임워크의 실행 설정
- PHP 서버 실행·디버깅 연동
- API 및 DB 작업 흐름 재사용

**완료 기준:** 선정 프레임워크의 일반 프로젝트에서 실행·디버깅·API 확인이 가능함.

## 공통 품질 목표

- 언어별 지원 기능과 필요한 외부 런타임을 명확하게 안내한다.
- 프로젝트 실행 명령과 환경 변수는 사용자가 확인하고 제어할 수 있게 한다.
- 프로젝트 간 설정을 분리하고 민감 정보는 평문으로 저장하지 않는다.
- 앱별 기능은 `apps/silk-be-studio`에 두고, 실제로 양쪽 앱에서 재사용되는 기반만 공용 패키지로 추출한다.
- 구체적인 언어 서버, 디버거, API 도구 및 프레임워크 선택은 각 단계의 검증 후 확정한다.
