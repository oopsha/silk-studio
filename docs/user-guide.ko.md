# Silk DB Studio — 사용자 가이드

*[English](./user-guide.md)*

Silk DB Studio 설치, 연결, 사용 전반을 다루는 종합 가이드입니다.

## 설치

1. [GitHub Releases](https://github.com/oopsha/silk-studio/releases)에서 **macOS** 또는 **Windows** 빌드를 다운로드합니다.
2. 평소 사용하는 OS 방식대로 앱을 설치/실행합니다.
3. 패키징된 빌드에는 **jdbc-agent**와 번들된 **Eclipse Temurin JRE 17**이 포함되어 있어, SQL/연결 기능을 위한 시스템 Java 설치가 **필요 없습니다**.

## 업데이트

Silk는 **자동으로** 업데이트를 확인합니다 — 실행 직후 한 번, 그리고 앱이 켜져 있는 동안 몇 시간마다 다시 — 그래서 직접 확인할 필요가 없습니다. 최신 버전이면 조용히 넘어가고, 새 릴리스가 있으면 다운로드·설치·재시작 여부를 물어봅니다. 원할 때 직접 확인하고 싶으면 **관리**(작업 표시줄의 톱니바퀴) → **업데이트 확인...**을 열면 됩니다. 업데이트는 Tauri 업데이터 서명으로 검증되며, 피드는 GitHub Releases의 `latest.json`입니다.

같은 톱니바퀴 메뉴의 **테마** 하위 메뉴에서 색 테마도 바로 바꿀 수 있습니다 — [모양과 테마](#모양과-테마) 참고.

## 연결 만들기

사이드바의 **연결** 패널을 열고 **새 연결**을 클릭하면 편집기 탭으로 연결 생성 폼이 열립니다. 입력 항목:

- **이름** — 앱 전체에서 이 프로필을 나타낼 이름.
- **드라이버** — **Oracle**, **SQL Server**, **MySQL**, **MariaDB**, **PostgreSQL** 중 선택.
- **호스트**/**포트**와 드라이버별 필드 — SQL Server/MySQL/MariaDB/PostgreSQL은 **데이터베이스**, Oracle은 **데이터베이스**와 **서비스 이름/SID** 선택. "JDBC URL 직접 입력" 옵션을 체크하면 구조화된 필드 대신 raw JDBC URL을 직접 입력할 수 있습니다.
- **사용자**/**비밀번호**, 그리고 **"이 비밀번호 저장"** 체크박스(기본 체크됨). 체크를 해제하면 이번 세션에서만 비밀번호를 사용하고 저장하지 않습니다.
- **기본 스키마**(Oracle, PostgreSQL) — 직접 입력하거나, 한 번 연결한 뒤 **스키마 로드**를 눌러 실제 데이터베이스의 스키마 목록에서 고를 수 있습니다.
- **시스템 개체 표시** — 데이터베이스 내부 스키마/개체를 탐색기 트리와 검색에 포함할지 여부.

**테스트** 버튼으로 저장 전에 자격 증명(및 아래의 터널 설정)이 유효한지 확인할 수 있습니다. 저장하면 **연결** 버튼이 나타납니다.

**비밀번호는 평문으로도, 내보내기 파일에도 절대 저장되지 않습니다.** AI 제공자 API 키와 동일한 방식으로, OS의 자격 증명 저장소(Windows 자격 증명 관리자, macOS 키체인, Linux Secret Service)를 거쳐 저장됩니다.

### 터널을 통한 연결

한 연결은 **터널을 한 종류만** 사용할 수 있습니다 — 하나를 켜면 다른 하나는 자동으로 꺼집니다.

**SSH 점프 호스트** — **"SSH 점프 호스트로 연결"**을 체크하고 점프 호스트/포트/사용자명을 입력한 뒤, 인증 방식으로 **비밀번호** 또는 **개인키**(선택적으로 키 패스프레이즈 포함)를 고릅니다. **"2단 SSH 로그인 체이닝 (ProxyJump)"**을 켜면 두 번 점프해야 닿는 데이터베이스를 위해 두 번째 SSH 로그인을 이어붙일 수 있습니다.

**AWS SSM 터널** — **"AWS SSM 터널로 연결"**을 체크하고 **AWS 리전**, **SSO Start URL**, **대상 인스턴스**(SSM 관리 대상 EC2 인스턴스 ID)를 입력합니다. 이때 연결의 호스트/포트 필드는 `localhost`가 아니라, 그 대상 인스턴스 입장에서 실제로 접근 가능한 데이터베이스 주소(예: RDS 엔드포인트)여야 합니다. **인스턴스 불러오기**를 누르면 AWS SSO로 로그인(브라우저 창에서 코드 로그인 진행)한 뒤 SSM이 접근 가능한 인스턴스 목록에서 고를 수 있습니다. 캐시된 로그인 세션이 만료되기 전까지는 다시 로그인할 필요가 없습니다.

### 연결 관리

- **이 연결로 새 쿼리**: 연결 행에 마우스를 올리거나 우클릭하면 전용 새 쿼리 액션이 나타납니다 — 현재 활성화된 연결이 무엇이든 상관없이, 그 연결의 SQL 방언으로 탭을 열고 해당 프로필에 바인딩합니다. 아직 연결되지 않은 프로필이면 탭은 즉시 열리고 연결은 백그라운드로 시작됩니다.
- **편집**: 저장된 연결을 클릭하면 값이 채워진 채로 폼이 다시 열립니다.
- **복제**/**삭제**: 연결 행에 마우스를 올리거나 우클릭하면 나타납니다. 삭제 전에는 확인을 물어봅니다.
- **내보내기**: 전체 또는 선택한 연결만 JSON 파일로 저장합니다. 비밀번호는 **절대 포함되지 않습니다**.
- **가져오기**: 이전에 내보낸 JSON 파일을 선택하면 이름 중복/연결정보 중복을 표시해주는 검토 화면이 뜨고, 가져올 항목을 고를 수 있습니다. 가져온 프로필은 항상 새로 생성되며(기존 것을 덮어쓰지 않음) 비밀번호는 저장되지 않은 상태로 시작하므로, 가져온 뒤 한 번 입력해야 합니다.

(연결 프로필과 별개로, 앱 **설정** 자체도 내보내기/가져오기가 가능합니다 — [설정 개요](#설정-개요) 참고.)

## 여러 연결 동시에 사용하기

**연결 개수 제한 없이 여러 개를 동시에 열어둘** 수 있습니다. 각 SQL 편집기 탭은 자신만의 쿼리 대상(연결, 그리고 Oracle/PostgreSQL이면 스키마, 그 외에는 데이터베이스/카탈로그)을 가집니다:

- **상태 바**(왼쪽 하단)에 포커스된 탭의 연결과 그 옆에 데이터베이스/스키마가 표시됩니다. 둘 중 아무거나 클릭하면 바꿀 수 있습니다.
- 편집기 탭에는 연결 이름이 흐린 접미사로 짧게 표시되며, 탭에 마우스를 올리면 전체 대상을 볼 수 있습니다.
- 실행/설명은 항상 *포커스된 탭*의 바인딩을 사용하며, 각 SQL 탭은 자신만의 결과 패널을 가집니다 — 한 탭에서 실행해도 다른 탭의 결과는 건드리지 않습니다.
- 탐색기는 연결된 프로필을 표시하며, 테이블의 데이터를 열거나 객체 편집기를 여는 작업은 그 객체 고유의 연결을 사용합니다.
- 연결이 끊긴 탭 바인딩은 재연결하거나 직접 바꾸기 전까지 그대로 유지됩니다 — Silk는 탭을 다른 연결로 조용히 전환하지 않습니다.

**현재 데이터베이스/스키마 전환**(상태 바 선택기, 또는 탐색기에서 카탈로그/스키마 우클릭 → "이 데이터베이스 사용"/"이 스키마 사용")은 클릭한 그 탭뿐 아니라, 같은 연결에 바인딩된 모든 열린 SQL 탭에 함께 적용됩니다 — 같은 연결의 탭들이 하나의 실제 데이터베이스 세션을 공유하기 때문입니다. **"기본 데이터베이스로 설정"**(카탈로그 기반 드라이버) 또는 **"기본 스키마로 설정"**(Oracle, PostgreSQL)을 사용하면 이 선택을 해당 연결 프로필의 기본값으로도 저장해서, 다음에 연결할 때도 그대로 적용됩니다.

## 트랜잭션

**자동 커밋**(설정 → 데이터베이스)을 꺼두면, 연결에서 실행한 쓰기 작업은 직접 확정하기 전까지 커밋되지 않은 상태로 남습니다. 연결에 커밋되지 않은 변경이 생기면, 그 연결에 바인딩된 탭 어디서든 상태 바에 **"커밋 대기 중"** 배지가 나타나고 바로 옆에 **커밋**/**롤백** 버튼이 붙습니다(같은 동작은 실행 메뉴와 명령 팔레트에서도 실행할 수 있습니다). 롤백은 먼저 확인을 묻고, 커밋은 바로 실행됩니다.

이 대기 중 상태는 탭이 아니라 **연결** 단위로 관리되므로, 같은 연결에 바인딩된 모든 탭이 같은 배지를 공유하며, 어느 탭에서 커밋/롤백하든 전부에 적용되고 그 연결의 열려 있는 결과 탭들도 함께 새로고침됩니다. 커밋되지 않은 상태로 연결을 끊거나 앱을 종료해도 Silk가 먼저 물어보지는 않습니다 — 그 이후 트랜잭션이 어떻게 되는지는 Silk가 아니라 데이터베이스 자체의 세션 종료 동작을 따릅니다.

## 데이터베이스 탐색하기

탐색기 트리는 연결마다 (SQL Server인 경우) 데이터베이스, 그 다음 스키마, 그 다음 개체 종류별 폴더(테이블, 뷰, 프로시저, 함수, 패키지 등), 그리고 개별 개체 순으로 보여줍니다.

- 탐색기 상단의 **필터 입력란**은 이미 로드/펼쳐진 트리 안에서만 실시간 부분일치 필터링을 합니다 — 아직 열어보지 않은 스키마까지 뒤지지는 않고, 다른 연결도 검색하지 않습니다.
- 필터 입력란 옆의 작은 검색 아이콘이나 **Ctrl+Shift+O**를 누르면, 이미 연결된 모든 프로필의 로드된 객체를 대상으로 타이핑 즉시 검색되는 퀵픽이 열립니다. 2글자 이상 입력하면 "연결 간 검색..." 항목이 나타나 실시간으로 데이터베이스 자체를 검색할 수 있습니다.
- 사이드바의 별도 **검색** 패널이 가장 강력한 옵션입니다 — 검색할 연결과 포함할 개체 종류를 고를 수 있고(인덱스와 동의어는 대개 원하는 결과가 아니라서 기본적으로 제외됩니다), 선택했지만 아직 연결 안 된 프로필은 **자동으로 연결한 뒤** 검색하며, 각 연결이 끝나는 대로 결과를 순차적으로 보여주고, 검색 중에는 취소 버튼이 나타나며, 타임아웃되거나 오류가 난 연결은 조용히 빠뜨리지 않고 표시해줍니다.
- 테이블/뷰를 더블클릭(또는 Enter)하면 **객체 편집기**가 열리고, 프로시저·함수·패키지·트리거는 **DDL 뷰어**가 열립니다.
- 개체를 우클릭하면 데이터 열기, 소스 편집/DDL 보기, 이름 복사, 이름 바꾸기, 삭제(뒤 두 가지는 드라이버와 권한이 허용하고, 읽기 전용 모드가 아닐 때만) 메뉴가 나타납니다.

## 데이터베이스 개체 보기/편집하기

**객체 편집기**(테이블, 뷰)는 두 개의 탭으로 구성됩니다:
- **속성** — 컬럼, 인덱스, 외래 키, 참조, 제약 조건, 트리거, 의존성 하위 섹션(일부는 테이블에만 해당 — 뷰는 실제 저장소가 없기 때문). 컬럼은 드라이버가 테이블 구조 편집을 지원하면 편집 가능하며, 그 외에는 모두 읽기 전용입니다. **단, 뷰의 DDL 섹션**은 드라이버가 지원하는 경우 저장/컴파일/스냅샷/히스토리 기능이 있는 편집 가능한 SQL 버퍼가 됩니다.
- **데이터** — 테이블/뷰의 행을 실행해서 보여줍니다(편집 방법은 아래 [쿼리 결과 다루기](#쿼리-결과-다루기) 참고).

**DDL 뷰어**(프로시저, 함수, 패키지, 트리거)는 선언/인자/의존성 하위 섹션을 보여줍니다(패키지는 스펙과 바디를 독립적으로 편집할 수 있어 더 세분화됩니다). 드라이버가 지원하면 선언/스펙/바디 섹션이 편집 가능한 버퍼가 됩니다.

**PL/SQL 개체 저장 및 컴파일**: **Ctrl+S**를 누르면, 파일로 저장하는 대신 생성될 SQL과 현재 데이터베이스와의 차이(diff), 경고를 보여주는 확인 대화상자가 열립니다 — 확인하기 전까지는 아무것도 적용되지 않습니다. **Ctrl+Shift+F9**는 명시적으로 컴파일합니다. 컴파일 오류는 편집기 안에 인라인과 마커로 표시되어 문제가 있는 줄로 바로 이동할 수 있으며, Oracle에서는 컴파일 시 저장 시점에는 나오지 않는 경고까지 잡아내는 추가 진단도 함께 실행됩니다.

## SQL 작성 및 실행

| 단축키 | 동작 |
| --- | --- |
| `Ctrl+Enter` | 현재 문장 실행 |
| `Ctrl+Shift+Enter` | 스크립트 전체(또는 선택 영역) 실행 — SQL Server에서는 `GO` 배치도 처리합니다. 첫 오류에서 멈추고 열려 있던 트랜잭션을 롤백하며, 결과 탭에는 배치마다 한 줄이 아니라 간단한 요약(성공 개수 + 오류)이 표시됩니다 |
| `Ctrl+Alt+E` | 현재 문장의 실행 계획(Explain) 보기 |
| `Ctrl+K` 다음 `Ctrl+O` | 이 탭의 연결/데이터베이스/스키마 대상 변경 |
| `Ctrl+Shift+P` | 명령 팔레트 |
| `Ctrl+K` 다음 `Ctrl+S` | 키보드 단축키(검색 가능, [키보드 단축키 커스터마이징](#키보드-단축키-커스터마이징) 참고) |
| `Ctrl+Shift+O` | 데이터베이스 개체 검색 — 연결된 모든 프로필의 테이블·뷰·프로시저 등을 대상으로 ([데이터베이스 탐색하기](#데이터베이스-탐색하기) 참고) |
| `Ctrl+,` | 설정 |

**명령 팔레트**(`Ctrl+Shift+P`)는 모든 명령을 현재 지정된 단축키와 함께 보여줍니다. 이름/ID/키로 입력해서 걸러낼 수 있고, 특별한 검색 문법 없이 단순 일치로 찾습니다.

쿼리 실행 중에는 **쿼리 취소** 동작(실행 메뉴 또는 명령 팔레트)이 나타나며, 연결 자체를 끊는 게 아니라 데이터베이스 드라이버에 실행 중인 문장의 취소를 요청합니다. 수동 트랜잭션 중이었다면 트랜잭션 자체는 취소 후에도 열린 채로 남으므로 커밋/롤백은 따로 해야 합니다. 실행이 끝나면 결과 패널에 행 수가 표시되고, 실행에 걸린 시간은 결과 패널이 아니라 **쿼리 기록**에 기록됩니다(아래 참고).

**실행 계획(Explain)**은 결과 행 대신 그 문장의 쿼리 플랜을 같은 결과 패널에 보여줍니다. `SELECT`뿐 아니라 편집기에 있는 어떤 단일 문장에도 동작하며, 각 방언 고유의 방식(Oracle의 `DBMS_XPLAN`, SQL Server의 `SHOWPLAN`, MySQL/PostgreSQL의 `EXPLAIN`)을 그대로 사용하므로 실제로 보이는 형식은 해당 데이터베이스가 반환하는 그대로입니다.

### SQL 자동완성(IntelliSense)

데이터베이스에 연결하고 SQL 편집기 탭을 연 뒤, **Ctrl+Space**를 누르거나 `.` 뒤에 입력하면 자동완성 제안이 열립니다. 제안 내용은 커서 위치와 포커스된 탭의 연결 방언에 따라 달라집니다:

| 상황 | 표시되는 것 |
| --- | --- |
| 빈 문장 / `;` 뒤 | 문장 시작 키워드만(`SELECT`, `WITH`, `INSERT` 등) — 함수는 아님 |
| `SELECT ` 뒤 | (`FROM`을 알 수 있는 경우) 컬럼과 방언별 함수(예: Oracle의 `TO_CHAR`) |
| `FROM ` / `JOIN ` 뒤 | 스키마, 테이블, CTE — 표현식 함수는 아님 |
| `FROM emp e` 다음 `e.` | `emp`의 컬럼 |
| `WITH c AS (SELECT id FROM t) … c.` | `id` 같은 CTE 컬럼 |
| 중첩된 `(SELECT … FROM dept d WHERE d.` 안에 커서 | 안쪽 `dept`만 — 바깥쪽 `FROM` 테이블은 노출되지 않아야 함 |
| `NVL` / `ISNULL` 같은 함수 수락 | 플레이스홀더가 있는 스니펫; `(`를 입력하면 인자 힌트가 보일 수 있음 |

큰 카탈로그에서도 반응성을 유지하기 위해 제안은 연결의 기본 스키마를 우선하며, 연결을 전환하거나 끊으면 캐시된 자동완성 메타데이터가 지워집니다.

### 드래그 앤 드롭

| 동작 | 결과 |
| --- | --- |
| 창에 `.sql`/텍스트 파일을 드롭 | 편집기 탭으로 열림 |
| 열려 있는 파일이 디스크에서 변경됨 | 깨끗한(수정 없는) 탭은 자동으로 다시 불러오고, 더티 탭은 먼저 확인을 물음 |
| 탐색기 개체를 SQL 편집기로 드래그 | 캐럿 위치에 `schema.object` 삽입 |
| 편집기 탭 드래그 | 탭 순서 변경 |

## 편집기 화면 분할하기

탭을 편집기 영역 가장자리로 드래그하거나, 명령 팔레트의 **오른쪽으로 편집기 분할**을 사용하면 두 번째 패널이 열립니다. 패널은 더 나눌 수 있고, 패널 사이 경계를 드래그해서 크기를 조절할 수 있습니다. **편집기 그룹 잠금**은 현재 패널에 표시된 내용을 고정시켜, 다른 테이블/객체를 열어도 그 패널이 바뀌지 않고 다른 패널에서 열리도록 합니다. **편집기 그룹 닫기**는 패널 전체와 그 안의 모든 탭을 닫습니다.

## 탭 닫기와 저장하지 않은 작업

Silk는 열려 있는 모든 탭의 내용 — 저장하지 않은 SQL/PL-SQL/DDL 버퍼를 포함해서 — 을 앱 재시작 후에도 자동으로 기억합니다. 그래서 앱을 끄기 전에 임시 쿼리를 굳이 저장할 필요가 없고, 다음에 열면 그대로 돌아와 있습니다.

다만 이 안전장치는 "앱을 재시작"하는 경우에 대한 것이지, 개별 "탭을 닫는" 것과는 다릅니다 — 탭을 닫으면 다음에 기억될 목록에서도 빠지기 때문에, 저장하지 않은 변경 사항이 있는 탭을 (×버튼, 사이드바의 열린 편집기 목록, 가운데 클릭, `Ctrl+W` 중 무엇으로든) 닫으려 하면 탭 종류와 상관없이 Silk가 먼저 확인을 물어봅니다.

## 쿼리 기록

작업 표시줄의 **쿼리 기록** 아이콘을 누르면 실행했던 모든 문장이 최신순으로 나열되며, 각 항목에는 상태, 시각, 소요 시간, 연결, SQL 미리보기, 결과/오류 요약이 함께 표시됩니다. 항목에서 다시 실행하거나, 새 편집기 탭으로 열거나, 현재 탭에 삽입하거나, **즐겨찾기**로 별표를 남길 수 있습니다. 필터 입력란으로 SQL 텍스트·요약·연결 이름·상태를 검색할 수 있습니다. 기록은 최근 100개까지만 보관되며 연결별로 따로 쌓이지 않고 전체가 공유됩니다 — AI 채팅의 "쿼리 히스토리 포함" 토글도 바로 이 저장소를 사용합니다.

## 쿼리 결과 다루기

단일 테이블에 대한 `SELECT`는 실행하면 결과 그리드에서 바로 편집 가능한 상태가 됩니다 — 단, 그 테이블에 기본 키가 있고 그 키 컬럼이 선택한 컬럼에 포함되어 있어야 합니다(뷰, 조인, 기본 키 없는 테이블의 결과는 읽기 전용으로 남으며, 읽기 전용 모드는 이 모든 것보다 항상 우선합니다).

- 셀을 클릭해서 **편집**합니다. 이미 저장된 행에서는 기본 키 컬럼을 편집할 수 없지만(저장된 행의 키를 바꿔봐야 의미가 없으므로), 새로 추가하거나 복제한 행에서는 새 키를 입력할 수 있도록 편집 가능합니다.
- **행 추가**는 편집 가능한 빈 행을 삽입하고, **행 복제**는 선택한 한 행을 그대로 복사한 뒤 기본 키만 비워서 새로 채우도록 합니다.
- 행을 삭제하면 즉시 지워지는 대신 삭제 대기 표시가 되며, 배지에 변경 대기 중인 행 수가 표시됩니다.
- 대기 중인 변경 사항이 있으면 **저장** 버튼이 활성화됩니다. 클릭하면 실제로 실행될 `UPDATE`/`INSERT`/`DELETE` 문과 행/셀 개수를 미리 보여주는 화면이 열리고, 확인해야만 실제로 적용됩니다.
- 도구모음의 컨텍스트 메뉴에서 **선택 영역 복사**, **선택한 행 복사**, **전체 복사(필터 적용됨)**, **CSV 내보내기(필터)**를 사용할 수 있습니다.
- 컬럼 헤더는 정렬을 지원하며, 쿼리 결과 설정에서 켜면 적용/초기화 버튼이 있는 컬럼별 필터도 사용할 수 있습니다.
- **컬럼 레이아웃 저장**은 해당 탭의 컬럼 너비/순서/정렬/필터 상태를 기억해둡니다.

## AI 채팅

Silk의 AI 채팅은 **직접 발급받은 API 키를 사용**합니다 — 지원되는 제공자 중 하나로 본인 계정을 연결하며, 쿼리나 스키마 데이터는 내 컴퓨터와 그 제공자 사이 외에는 어디로도 전달되지 않습니다.

### 설정하기

1. **설정**(`Ctrl+,`) → **AI**를 열고 활성화합니다.
2. **제공자**를 선택합니다 — Gemini, OpenAI, Anthropic, 또는 **사용자 지정**(OpenAI API와 호환되는 아무 엔드포인트든, Base URL 필드를 함께 입력).
3. 미리 정의된 목록에서 **모델**을 고릅니다(사용자 지정이면 직접 입력).
4. **API 키**를 붙여넣고 저장합니다. **연결 테스트**로 실제로 동작하는지 미리 확인할 수 있습니다.

API 키는 연결 비밀번호와 동일하게 OS 자격 증명 저장소에 저장되며, 평문 설정 파일에는 절대 남지 않습니다.

### 사용하기

- **Ctrl+Shift+A** 또는 사이드바에서 채팅 패널을 엽니다.
- 대화는 하나만 유지되며, **새 AI 채팅**을 누르면 초기화됩니다(되돌릴 수 없음). 대화 기록은 앱을 재시작해도 유지됩니다.
- 어시스턴트가 무엇을 보게 할지는 설정 → AI의 네 가지 토글로 조절합니다: **스키마 컨텍스트 포함**(탐색기에서 살펴본 내용 요약), **에디터 선택 포함**(활성 탭에서 선택한 텍스트, 아무것도 선택 안 했으면 버퍼 전체), **쿼리 히스토리 포함**, **열린 PL/SQL 의존성 포함**(현재 열려 있는 PL/SQL 개체 탭의 소스/의존성/컬럼).
- 어시스턴트는 개체 소스, DDL, 의존성, 컬럼을 조회하고 개체의 편집기 탭을 대신 열어줄 수 있지만, **직접 쿼리를 실행하거나 데이터베이스에 쓸 수는 없습니다**. SQL을 제안할 때는 코드 블록으로 표시되며 **검토**, **복사** 버튼과 함께, 설정 → AI에서 **SQL 실행 허용**을 켰다면 **실행...** 버튼이 나타나 — 클릭하면 실제 실행 전에 확인 대화상자가 열립니다.

### AI 호출 로그

**도움말 → AI 호출 로그**는 AI 제공자에게 보낸 모든 요청의 목록을 보여줍니다 — 시각, 제공자/모델, 성공/실패 여부, 토큰 수, 예상 비용, 소요 시간. **프롬프트, 응답, API 키는 절대 저장되지 않습니다** — 메타데이터만 남기므로, 실제로 무슨 내용을 주고받았는지 확인하는 용도가 아니라 사용량/비용을 지켜보고 실패를 잡아내는 용도입니다. **내보내기**는 JSON 파일로 저장하고, **지우기**(확인 필요)는 이 로그만 비우며 채팅 기록에는 영향을 주지 않습니다.

## 설정 개요

**Ctrl+,**로 설정을 엽니다:

- **모양** — 언어, 색 테마, UI 글꼴 크기.
- **에디터** — 글꼴 크기, 탭 크기, 줄 번호, 미니맵, 고정 스크롤, 자동 줄바꿈.
- **데이터베이스** — 쿼리 타임아웃, 자동 커밋, **읽기 전용 모드**, 탐색기 미리 불러오기 동작, 바인드 파라미터 표기 방식. 읽기 전용 모드는 모든 연결에 한 번에 적용되는 단일 스위치입니다 — 모든 쓰기 문장(`INSERT`/`UPDATE`/`DELETE`/DDL 등, 저장 시점이 아니라 실행하려는 그 순간에 차단), 탐색기의 이름 바꾸기/삭제, 쿼리 결과 그리드 편집 저장, PL/SQL 저장/컴파일, AI가 제안한 SQL 실행을 모두 막습니다 — `SELECT` 같은 읽기 전용 문장과 Explain은 평소대로 동작합니다.
- **쿼리 결과** — 최대 행 수, 행 높이, 컬럼 필터 등 그리드 관련 동작.
- **AI** — 제공자, 모델, API 키, 위의 컨텍스트/실행 토글들.

여기서 앱 **설정** 전체를 JSON 파일로 내보내기/가져오기할 수도 있습니다 — 이는 연결 프로필과는 별개이며 연결 정보는 포함하지 않습니다.

## 언어

1. **설정**(`Ctrl+,`) → **모양**을 엽니다.
2. **언어**를 **English** 또는 **한국어**로 설정합니다.
3. 메뉴, 설정, 탐색기, 쿼리 패널, 대화상자, AI 채팅을 포함한 전체 UI가 즉시 바뀌며, 선택한 값은 다음 실행 때도 유지됩니다.

저장된 설정이 없는 첫 실행에서는 OS/브라우저 언어를 따릅니다(한국어 로캘이면 한국어, 그 외에는 영어).

## 모양과 테마

설정 → 모양 → **색 테마**에서 **시스템**, **다크**, **라이트** 중 고를 수 있습니다. **시스템**을 선택하면 OS의 라이트/다크 설정을 자동으로 따라갑니다. 같은 세 가지 옵션은 톱니바퀴(관리) 메뉴의 **테마** 하위 메뉴에서도 선택할 수 있어, 설정을 열지 않고도 바로 바꿀 수 있습니다.

## 키보드 단축키 커스터마이징

**Ctrl+K** 다음 **Ctrl+S**, 또는 관리 메뉴에서 검색 가능한 **키보드 단축키** 편집기를 엽니다.

- 입력해서 명령 이름이나 현재 키로 필터링합니다.
- 행의 연필 아이콘을 클릭한 뒤 원하는 키 조합을 누르면 그 자리에서 캡처되고, 체크 표시를 누르면 적용됩니다.
- 이미 다른 곳에서 쓰이는 조합이면 어떤 명령과 충돌하는지 경고가 뜨지만, 그래도 설정하는 것을 막지는 않습니다.
- 기본값에서 바꾼 행에는 "변경됨" 배지가 붙고, 초기화 아이콘으로 원래대로 되돌릴 수 있습니다.
